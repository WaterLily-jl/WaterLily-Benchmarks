# Profiling

[`profile.sh`](https://github.com/WaterLily-jl/WaterLily-Benchmarks/blob/main/profile.sh) profiles the solver kernels on NVIDIA GPUs. The kernels, generated by [KernelAbstractions.jl](https://github.com/JuliaGPU/KernelAbstractions.jl), are traced with [NVTX.jl](https://github.com/JuliaGPU/NVTX.jl) ranges, which live in the [`profiling`](https://github.com/WaterLily-jl/WaterLily.jl/tree/profiling) branch of WaterLily. `profile.sh` checks out that branch in `$WATERLILY_DIR` and updates its environment, whatever `-w` says.

```sh
./profile.sh -ns nsys -c "tgv sphere cylinder" -p "8 5 6" -s 1000 -r 2
./profile.sh -ns ncu -c cylinder -p "4,5,6" -s 20 -k "327 355"
```

The runs use the CUDA environment, `gpu/CUDA`, which `profile.sh` makes again on every call (see [Environments](environments.md)), and the plots use the plotting environment, which has to be instantiated once.

## Options

| Option | Default | Meaning |
|---|---|---|
| `-ns`, `--nsight` | `nsys` | `nsys`, `ncu`, or both: `"nsys ncu"` |
| `-r`, `--run` | `0` | `0` post-processes existing data, `1` profiles, `2` profiles and then post-processes |
| `-c`, `--cases` | none | cases to profile |
| `-p`, `--log2p` | none | sizes, one entry per case; comma-separated sizes are profiled one by one with `ncu` |
| `-s`, `--max_steps` | `1000` | time steps |
| `-ft`, `--float_type` | `Float32` | float type |
| `-k`, `--kernels` | none | kernels to profile with `ncu`, e.g. `"327 355"` |
| `-b`, `--backends` | `CuArray` | backend |
| `-v`, `--versions` | the `julia` on the `PATH` | Julia version |
| `-wd`, `--waterlily_dir` | `$WATERLILY_DIR` | the WaterLily.jl clone |
| `-dd`, `--data_dir` | `data/profiling` | profiling data, one directory per case |
| `-pd`, `--plot_dir` | `plots/profiling` | plots of the post-processing |

## Nsight Systems

With `-ns nsys`, each case runs as

```sh
nsys profile --sample=none --trace=nvtx,cuda --output=<data_dir>/<case>/<case>.nsys-rep --export=sqlite --force-overwrite=true julia src/profile.jl <case arguments>
```

The post-processing (`-r 0` or `-r 2`) reads the time spent in each NVTX range with `nsys stats -r nvtx_gpu_proj_sum` and plots the share of each kernel with CairoMakie. The reports also open in the Nsight Systems GUI.

## Nsight Compute

With `-ns ncu`, the kernels given by `-k` are profiled with `ncu --set full`, one report per size in `<data_dir>/<case>/`. Open the reports in the Nsight Compute GUI.
